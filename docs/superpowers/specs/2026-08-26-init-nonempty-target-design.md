# fix(scaffold): refuse non-empty init targets

## Контекст

`scaffold.InitService` разворачивает embedded templates напрямую в заданный каталог. Для каждого файла используется `os.WriteFile`, поэтому совпадающие существующие файлы заменяются без предварительной проверки.

## Проблема

Ожидаемое поведение: команда и API для создания нового сервиса не изменяют каталог, в котором уже есть пользовательские данные.

Фактическое поведение: init в непустой каталог частично создаёт структуру и без предупреждения перезаписывает совпадающие файлы, например `go.mod`.

Практический риск: потеря незакоммиченных или иных существующих данных и частично изменённый каталог при последующей ошибке.

Текущий источник: `internal/scaffold/scaffold.go`, функция `InitService`.

## Решение

- Один раз вычислить `targetDir := filepath.Clean(dir)` и использовать его и для проверки, и как корень всех последующих записей. Это не позволяет `dir == ""` обойти защиту: он корректно означает текущий каталог (`.`).
- До первого `MkdirAll` или `WriteFile` проверить состояние `targetDir`.
- Несуществующий target разрешён: текущая генерация создаёт его.
- Существующий пустой каталог разрешён: текущее поведение сохраняется.
- Существующий непустой каталог отклоняется понятной ошибкой. Учитываются любые entries, включая скрытые файлы.
- Если target существует, но не является читаемым каталогом, вернуть исходную filesystem error без попытки записи.
- Проверка выполняется один раз перед обходом embedded templates; дополнительная staging-инфраструктура не вводится.

Публичная сигнатура `InitService` не меняется. Семантика для непустого target намеренно становится fail-fast и недеструктивной.

## Проверка

- Создать временный каталог с sentinel-файлом `go.mod` и известным содержимым.
- Вызвать `InitService` и ожидать ошибку.
- Повторно прочитать sentinel и убедиться, что bytes не изменились.
- Убедиться, что `zengo.textproto` и другие scaffold-файлы не появились.
- В отдельном безопасном regression test временно сделать непустой test-каталог текущим, передать `dir == ""` и проверить тот же отказ без записи.
- Существующие тесты уже покрывают успешную генерацию в пустой каталог для textproto и YAML и должны остаться зелёными.

## Вне scope

- `--force`, overlay/merge mode, backup и интерактивное подтверждение.
- Атомарная генерация через staging directory.
- Межпроцессная блокировка target между проверкой и записью.

## Критерии приёмки

- При непустом target `InitService` возвращает ошибку до любой записи.
- Проверяемый target и корень генерации всегда совпадают, включая `dir == ""`.
- Все существовавшие bytes и структура каталога остаются без изменений.
- Несуществующий и существующий пустой target продолжают поддерживаться.
- Все существующие тесты проекта проходят.
